# 自研导出器性能与能力审查

> 本文主体保留 1.2.0 的历史审查。1.3.0 已采用强类型数值 JSON、等价块拷贝哈希、有界参数缓存和法线处理优化，并新增独立设置、贴图与附加数据导出；当前范围见 [README](README.md)。2026-10-28 的三轮合成写包结果位于 `artifacts/independent-1.3-bench/benchmark-results.json`，与旧记录的运行时/机器负载不受严格控制，不据此推算实际 Revit 导出加速。真实工程性能仍待同模型、同视图、同选项计时。

本审查针对现有 1.2.0 自研源码。用户报告相对原导出器变慢，但本轮没有运行 Revit、打开工程或对 BOS 作计时。因此下述是可由代码证明的工作量与待测热点，不是实际工程的速度倍数结论。生产 DLL、安装器和用户工程未因本审查修改。

## 可定位的成本

| 位置 | 代码事实 | 最小兼容改进方向 |
| --- | --- | --- |
| `RevitApp.cs`：`OnElementBegin`、`Parameters` | 每次元素回调都枚举实例参数，对 Double/ElementId 调 `AsValueString`，立即序列化整个属性组。链接文档多次放置或重复回调时，同一来源元素的参数仍会重新读取。即使最后无网格，也已读写参数。 | 在一次导出内按文档作用域 + Element.UniqueId 缓存实例参数快照，来源/链接放置标识单独生成。先保留全部属性，不以“无网格就丢弃”损失树节点。记录参数数目/格式化次数及耗时，区分 API 和 JSON 成本。 |
| `RevitApp.cs`：`SharedProperties` | **类型和族参数已有缓存**，不是每个实例都全量读取类型/族参数。类型名称/族名称、Level 查询仍逐元素读取。 | 保留现缓存；可缓存类型元信息和文档内本地楼层信息。世界标高仍需按链接放置变换计算，不能缓存成一个世界高度。 |
| `RevitApp.cs`：`OnPolymesh` | 每个三角形分配 `int[3]`，无条件计算叉积/归一化备用法线；每个 corner 另创建 XYZ 差值并重新检查/归一化法线。即使有效法线已提供，备用法线成本仍发生。 | 按法线分布只归一化一次：单面一次、每 facet 一次、每顶点一次；仅缺失或零法线时计算 fallback。对比几何/法线/镜像 fixture 后再改生产。 |
| `RevitApp.cs`：`OnPolymesh` | 全部网格展开为 3T 顶点，忽略原始 point/index 复用。这保护锐边/不同 UV，但连续光滑区域也被展开。 | 后续可按 `(源顶点索引, 法线, UV)` 复用 corner；不能仅按位置合并，否则锐边/贴图接缝会损坏。先记录输入点数与输出顶点数。 |
| `PackageWriter.cs`：`AddGeometry` | 每一次几何提交先逐数值写 BinaryWriter/MemoryStream，再计算 SHA，最后才通过 HashSet 识别重复。复用只省后续几何 JSON，**不省前面的网格展开/法线/哈希**。20,000 三角形的展开数组对应约 4,080,008 字节哈希输入。 | 先量化重复率与哈希耗时。可用逐字节等价的块拷贝原型检验编码成本；若用 Revit 级几何身份作缓存，必须证明实例裁切/可见性/材质差异不会改变几何，不能直接以 FamilySymbol/TypeId 跳过实例。 |
| `Json.cs`：`IEnumerable` 分支 | 数值数组走非泛型枚举，每个 double/int 装箱，进入动态类型判断，再对每个 double 作 `R` 格式化。20,000 三角形有 480,000 个 double 与 60,000 个 int。 | 在保持完全相同数值与 UTF-8 输出的前提下，为 double[]/int[] 增加专门路径；先用独立原型和真实数据验证收益。不能降低精度或换近似数值来制造加速。 |
| `PackageWriter.cs`：`RecordSink`、`WriteText` | 每条记录先生成完整字符串，再拷入分块 StringBuilder；Flush 再生成整块字符串、包裹字符串、UTF-8 编码并以 Optimal deflate 压缩。大几何字符串/数组可进入 LOH，压缩发生在 Revit 主调用链。 | 先拆分 JSON、UTF-8、ZIP、磁盘成本。流式序列化和适当压缩级别可能有用，但需保留限额/原子提交并实测速度与 ZIP 大小取舍。 |

没有证据的指责应排除：目前 `FilteredElementCollector` 只在 ExportContext 构造时扫一次链接实例；DocumentScope 也已缓存。源码中没有每构件重复进行全模型 collector 的路径。Dictionary/HashSet 查询本身平均为常数时间，主要成本在查询前的大数组构造、格式化和 SHA 工作，不能把“用了字典”当作根因。

## 与用户要求的原选项存在的差距

| 原能力 | 1.2.0 自研现状 |
| --- | --- |
| 贴图 | 固定 `textureImages:false`，只保留颜色/透明度。没有贴图选择、解析或复制。 |
| 系统树 | 没有 MEP 系统成员归属与系统树输出。属性中可能有系统名称文字，不能等同系统树。 |
| 空间树 | 只有楼层/分类分组，没有房间/空间/区域成员与空间树。 |
| 专业树 | 没有专业映射或专业树，只写 Revit category。 |
| CAD | 可见 CAD 的三维网格可能由 CustomExporter 隐式输出，但没有 CAD 开关、二维曲线采集或 CAD 完整性保证。 |
| 轴网 | 没有轴网曲线、标头或专用实体；碰巧出现的元素属性不等于轴网内容。 |
| 二维 | Availability/Execute 明确限制非模板 View3D；二维视图、线、标注不支持。 |
| 视图/路径 | 只写当前视图 name/UniqueId，没有视图列表、相机、路径或选项配置。旧选项的准确语义仍需从原导出器确认。 |
| 导出内容计数 | 只有回调组件数、唯一几何数、放置三角形数；没有贴图/系统/空间/专业/CAD/轴网/二维/视图分类计数。组件数包含无节点容器和重复回调后缀，不能当作唯一源构件数。 |

这些是功能缺口，不能靠加复选框或把旧名称贴到新 pipeline 上补齐。应先保留成熟导出入口及其原选项；独立自研路径在完成等价能力与同模型/同选项验收前，不应被当作无损替代。

## 独立诊断基准

```powershell
.\tools\bright-revit-exporter\Benchmark-Exporter.ps1 -Triangles 5000 -Instances 30 -Trials 3
```

该程序只编译当前 `Json.cs`/`PackageWriter.cs` 与诊断 fixture，不引用 Revit API，不参与生产 DLL 构建。输出位于 `artifacts/benchmarks`，包含 JSON 报告和人工合成模型 ZIP。阶段包括首次几何、重复几何验证/哈希、数值 JSON、实例记录、最终 JSON flush/Optimal ZIP/原子提交，并记录各阶段 GC 次数。

两个**仅在诊断程序内**的原型分别检验块拷贝哈希和强类型数值 JSON；先断言完整哈希/数值字符串等价，再测成本。它们没有进入生产源码。结果只说明所用运行时、合成网格与指定规模下的托管写包成本，不包含 Revit 网格生成、参数 API、BOS、纹理或树构建，也不能推算真实工程倍数。阶段首次调用含 JIT/初始化；应比较多轮结果，而非拿单个数字作承诺。

本机一次三轮诊断记录（5,000 三角形/网格、30 个共享实例；CLR `4.0.30319.42000`、64 位进程）的每轮阶段中位数如下。每份哈希输入是 1,020,008 字节；合成 ZIP 为 65,439 字节，模型 JSON 为 588,851 字节。

| 阶段 | 每次中位耗时 |
| --- | ---: |
| 当前首次网格：校验 + 哈希 + JSON | 71.807 ms |
| 当前重复网格：校验 + 哈希 | 4.918 ms |
| 当前四个数值数组 JSON | 49.933 ms |
| 仅诊断的强类型 JSON 原型 | 37.323 ms |
| 仅诊断的块拷贝校验/哈希原型 | 2.628 ms |
| 30 个实例节点/构件记录 | 2.372 ms |
| 最终 JSON flush + Optimal ZIP + 原子提交 | 30.286 ms |

这些阶段有重复诊断工作，不能直接相加为一次真实导出的总时间。数字只用于说明可隔离、可复测的写包成本；它们不构成完整导出器加速承诺。报告还验证了 30 个构件/节点、1 份共享几何及 150,000 个放置三角形。

下一步真实诊断应由用户在同一份工程、同一视图和原选项下主动执行：记录参数读取/格式化数量、原始/展开顶点数、实际网格重复率、JSON/ZIP 字节和分阶段总耗时。计时应在元素/网格块/写包阶段累计，避免每个顶点调用 Stopwatch 反而干扰结果。先保留输出内容，再根据证据选择缓存、法线、序列化或压缩改动。
