# 参与 Bright Vision 开发

欢迎对可复现问题、构建说明、界面和已有计算边界提交改进。先阅读各模块 README、BUILDING 和功能分期；不要把计划中的功能写为已经交付。提交到本仓库的自有贡献按项目 Apache-2.0 许可提供，原有第三方许可证与署名应保留。

## 报告问题

描述产品版本、操作系统、Revit 年份／完整 build（如适用）、复现步骤、预期与实际结果。量值问题注明单位、范围、阶段／设计选项、规则方法及失败状态；性能问题提供同模型、同视图、同选项和输出位置的可比较数据。

请用有权公开的最小合成样例。不要上传客户 RVT、导出 ZIP、图纸、真实项目设置、带路径／人员信息的日志、厂商 API DLL 或安装包。截图和日志先删去私有内容。安全问题按 SECURITY 处理。

## 修改和验证

Web 查看器使用 Node.js 26。在 `tools/bim-viewer` 中执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
```

源 CI 会检查纯源码和 Web 构建；缺少已审查 Revit 模块时，相关集成测试明确 SKIP。不能将 SKIP 视为完整 Windows 包或实际 Revit 验收通过。完整构建流程见各模块 BUILDING。

计算修改应有独立可核定的小算例，分别检查基础事实、逐条台账、单位、缺失／失败状态和结果，不能只断言总数与实现一致。几何候选不等于实际交集；原生净参数不能当独立毛量再扣。新规则、构件、链接或年份须单列支持范围和验收证据。

Revit 测试需要开发者合法取得 API 与专用样例副本。保留运行中保护、临时注册的 nonce／所有权、源文件身份和事务回滚；不要跳过发布者验证、许可或登录提示。不要使用正在编辑的用户工程做夹具。

官方升级需维持产品注册、协议及安装所有权兼容。不要在普通功能修改中随意改 AppId、NSIS GUID、AddInId 或受管理文件名；如确需迁移，应有明确方案和回滚验证。fork 可按品牌说明使用自己的名称和身份。

## 提交与发行边界

PR 应说明具体问题、改后行为、验证方法及仍未覆盖的场景。不要加入 `node_modules`、构建输出、原始模型、API cache、安装／恢复记录、密钥或令牌。新增第三方依赖时同步原始许可和通知。

公开源码不要求提交预编译模块。维护者从当前源码构建后，显式审核模块与更新本机字节锁；默认打包不得自动接受任意下载 DLL。发行资产、在线更新配置和发布者签名是独立步骤，普通贡献不自动发布 Release 或修改更新信任源。
